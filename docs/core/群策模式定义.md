# 群策模式——轻量级 Agent 协作模式

**定位**：治理层协作谱系中介于"群聊/工作群"与"Committee session"之间的中间态。

## 协作谱系

```
单 Agent 执行 ──→ 群聊/工作群 ──→ 群策模式 ──→ Committee session（正式）
（无协作）        （松散交流）     （自由讨论）   （表决·决议·终裁）
```

## 核心特征

| 维度 | 群策模式 | Committee session |
|------|---------|-------------------|
| 召集者 | 无固定（Agent 自发） | 明确的 convener |
| 参与 | 自愿、不强制 | 按角色/议题定员 |
| 讨论规则 | 自由发言、允许跑题 | 就座→发言→表决流程 |
| 产出 | 无强制决议 | 决议 + 仲裁意见 |
| 终裁 | 无 | 用户可终裁 |
| 事件订阅 | 无（不投递） | `SessionConvened` / `SessionResolved` |
| 适用场景 | 自审视、编码规范讨论、早期探索 | 合规审计、冲突裁决、修宪表决 |

## 与现有机制的关系

```
needsMultiPerspective 节点
    │
    ├─ 需要决议 → Committee session（T6 协议）
    │
    └─ 只需讨论 → 群策模式（本文档）
```

- 群策模式不注册到 Scheduler，不走 PipelineObserver 事件管道
- 不产生 `SessionConvened`/`SessionResolved` 事件
- Agent 通过 `directChat()` 直连 LLM 参与讨论，不抢任务板节点
- 记录群策过程的方式：由 MetaAgent 在事后打一份摘要写入 Episodic 记忆
