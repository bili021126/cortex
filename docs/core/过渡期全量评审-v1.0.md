### 需要更新的条款

| 条款 | 旧值 | 新值 |
|------|------|------|
| 包数量 | 26 | 29 |
| `REACT_MAX_LOOPS` | 硬编码 20 | `executeStepTimeoutMs` 统一走 config |

| 构建工具 | tsc composite build | 已知天花板，Core-3 迁移 tsup |

### 需要新增的条款

| 条款 | 内容 |
|------|------|
| §事件循环隔离 | CPU 密集型操作必须走 `WorkerPool`。同步操作不得阻塞主线程超 50ms。 |
| §硬验证优先 | 凡可零 token 验证的必须硬验证（git diff / tsc / eslint / FSM 查表）。LLM 诊断过规则引擎后才入通知管道。 |
| §恢复导向拒绝 | 硬验证 FAIL 不静默丢弃——附拒绝原因回传发射方，模型自动修正。 |
| §三轴动作表 | 每个治理事件在三轴上必须有明确的消费方和动作定义。 |
| §Plan 模式三审链 | 甘雨规划→`.review` 三省审议→`.approve` 执行→调度器驱动 |
