## 〇、总纲

### 〇.1 治理层的本质

治理层只做两件事：**暴露不可靠，治理内化。**

- 暴露不可靠：检测异常、上报违规、阻断危险操作。治理层是系统的"免疫系统"——不执行任何业务逻辑，只观察和防御。
- 治理内化：将已验证可靠的模式沉入系统结构——不是"建立一个政府来管理"，而是"让规则在运行中自然执行"。

### 〇.2 三轴——治理层的不可变骨架

```
事轴（命令流，自上而下）
  用户意图 → MetaAgent 规划 → TaskBoard → Scheduler → Agent 执行
  职责：意图传导。轴上的组件不决策——只传递和拆解。

权轴（约束流，自下而上）
  Agent 失败/异常 → SafeErrorReporter → 重规划 → 用户裁决
  职责：异常上报。约束往上报，决策在顶层。

横切（监督流，独立于事轴）
  PipelineObserver 独立订阅所有事件。DocGovernAgent 独立审计。
  职责：旁观。横切不参与命令流——只看、只报、不指挥。
```

**三轴是治理层的不可变骨架。** 历史上所有概念——委员会、纪检委、五路监督、三省六部、监理——都是这三轴在不同抽象层级上的映射。概念可以换三代名字，轴不变。

### 〇.3 治理层在六层架构中的位置

治理层是六层中的"全流观察者"。它不产生业务产出——只观察其他五条流（交互/规划-执行/技能-工具/记忆）的运转，在异常时触发修正。治理层是唯一的单向接收者——所有层向它发射事件，它不向任何层回写（唯一例外：经用户裁决后的修宪写入）。

## 二、概念映射——历史概念在三轴上的位置

历史上治理层讨论产生了大量概念。它们不是需要逐项"实现"的清单——是**三轴在不同抽象层级上的映射**。以下逐概念标注：隐喻本意、三轴位置、代码中的实际形态、以及为何不需要独立 Agent。

### 2.1 委员会 → 事轴×横切的交汇点

| 维度 | 说明 |
|------|------|
| **隐喻本意** | 常设委员会管审计，临时委员会管裁决 |
| **三轴位置** | 常设=横切·合规审计。临时=事轴·多视角并行 |
| **代码形态** | 常设→DocGovernAgent 三大审计。临时→needsMultiPerspective + dispatchMulti |
| **为何不需要独立 Agent** | 审计已经在 DocGovernAgent 中闭环。多视角审议已经在 dispatchMulti 中闭环。Committee session 作为独立的审议会话机制是 Core-3 升级项，非当前缺失。 |

### 2.2 纪检委 → 权轴上的完整上报路径

| 维度 | 说明 |
|------|------|
| **隐喻本意** | 巡视→发现→立案→审理→处分 |
| **三轴位置** | 权轴·自下而上的异常上报链 |
| **代码形态** | 巡视=PipelineObserver。立案=DocGovernAgent 审计发现。审理=修宪三审。处分=ConfirmGate+amending |
| **为何不需要独立 Agent** | 查办分离原则已兑现——PipelineObserver 只能 emit、DocGovernAgent 能审查不能惩罚、ConfirmGate 是物理关卡。五环监督链全部有代码对应。 |

### 2.3 五路监督 → 横切上的五个切入角度

## 四、原则在治理层中的定位

七条不可变原则在治理层中的约束关系（详见 [七原则五流定位](Cortex-七原则-五流定位.md)）：

```
L0 全流约束
  └── 原则五（统一可观测）→ 横切·PipelineObserver 全流管道
        │  没有它，其他原则的违反无法被检测

L1 流间交叉约束
  ├── 原则一（确认锚定）   → 权轴·ConfirmGate + 横切·DecisionGateBridge
  ├── 原则四（可追溯性）   → 权轴·ConfirmGate.recordDecision
  └── 原则六（用户终裁）   → 权轴顶端·修宪三审 + 横切·圆桌裁决

L2 流内结构约束
  ├── 原则二（非对称均衡） → 事轴·MetaAgent×Agent 边界
  ├── 原则三（边界集中）   → 权轴·Toolkit 统一入口
  └── 原则七（宪法自约束） → 横切自指涉·GovernanceLoop
```

## 五、治理层与其他层的关系

```
交互层        → 用户裁决进入权轴。修宪裁决进入横切。
规划-执行层   → 事轴的主体。所有事件 emit 进入横切。
技能-工具层   → 工具调用经权轴（ConfirmGate）拦截。
记忆层        → 被横切（ConsistencyLayer）校验。
治理层        → 只接收、不写入。唯一例外：经用户裁决后的修宪。
```

治理层是单向接收者——所有层向治理层发射事件，治理层不向任何层回写。
