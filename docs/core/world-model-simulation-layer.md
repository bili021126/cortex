# Cortex 世界模型仿真层 · 设计定稿

> Core-2 参考设计 | 2026-07-04

---

## 一、定位

在记忆系统和场景调度层之间插入一个轻量级仿真层。不是独立子系统——是一段胶水代码，插在两层之间的缝隙里。定位是"草案引擎"：预测任务执行风险、资源消耗和失败概率，产出带置信度标签的候选 TaskGraph。

---

## 二、架构坍缩

### 初次构想（四层，已废弃）
- 原子事实链：三元组 {subject, predicate, object, confidence, trace}
- 贝叶斯因果图：外部推理引擎
- 历史案例库：完整编排案例
- 参数权重矩阵：风险基率 + 资源系数 + 因果强度

### 坍缩后的最终形态（两层）
- **仿真提示词生成器**：从记忆系统检索原子事实 + 历史偏差 → 组装结构化 prompt → LLM 产出 SimulationResult
- **偏差回传归档器**：对比预测 vs 实测 → 生成偏差报告 → 异步归档到记忆系统

**坍缩核心认知**：LLM 本身就是最强大的因果推理引擎。不需要在外部再建贝叶斯网络——LLM 的参数里已经有一个隐式的因果模型，比任何手写推理网络都灵活。唯一需要写代码的是胶水——把数据喂给 LLM 和把 LLM 的输出接回系统。

---

## 三、SimulationResult 结构

```typescript
interface SimulationResult {
  overall: "low" | "medium" | "high";
  per_step: Array<{
    step: number;
    risk: "low" | "medium" | "high";
    confidence: number;  // 0.0 - 1.0
  }>;
  uncertain_nodes: number[];
  resource_estimate: {
    api_calls: number;
    files_touched: number;
  };
}
```

### 多视角共识
单个 LLM 的 SimulationResult 不可靠。直接复用自审视系统的对称攻防引擎——两个不同 system prompt 分别产出 SimulationResult，取共识部分为最终输出，分歧部分标记为 `uncertain_nodes`。不是重新造一个验证机制，是复用已有的攻防管线。

---

## 四、仿真层 × 场景调度层联动

### 策略映射
```
overall == "low"    → DSA（激进，直接执行，少验证）
overall == "medium" → CSA（保守，并行推测，多点验证）
overall == "high"   → HCA（人机协同，每步暂停确认）
```

### 可加重方向
1. 不确定点自动触发并行推测执行
2. 历史偏差均值降级检索策略
3. 闭环信号：仿真层预测 → 调度层选策略 → 执行 → 偏差回传 → LLM 自我修正

---

## 五、偏差回传闭环

不是"log 错误"——是让下一次 SimulationResult 被上一次的偏差调制。

```
仿真层预测 → 调度执行 → 实测结果
                ↓
           偏差计算（预测 vs 实测）
                ↓
   偏差归档器 → 记忆系统（异步，不阻塞编排）
                ↓
   下次仿真 prompt 追加："上次预测 {high} 但实际 {顺利通过}，请调整"
```

**冷启动**：第一次运行无历史偏差。Phase 1 用 LLM 零样本预测。Phase 2 有了偏差积累后切换。

## 六、原子事实链

世界模型的最小数据单元。三元组结构：

```typescript
interface AtomFact {
  subject: string;
  predicate: "depends_on" | "has_risk" | "consumes";
  object: string;
  confidence: number;
  trace: string[];   // 可追溯证据链
  status: "active" | "stale";
}
```

### 因果剪枝原则
只保留对后续推演有因果影响的节点。从盘古 Flash 的轻量化状态缓存偷来的思想：不是存得越多越好，是存得越准越好。

---

## 七、Redis 运行时加速层

Redis 不是新子系统——只是已有模块的运行时热缓存。所有数据以记忆系统为持久化源，Redis 只做热数据加速。

| 缓存结构 | 类型 | TTL | 用途 |
|----------|------|-----|------|
| 临时偏差热缓存 | Hash | 3600s | 避免每次穿透到记忆系统 |
| SimulationResult 缓存 | Hash | 600s | 编排周期结束自动过期 |
| 滑动窗口统计 | Sorted Set | — | 近期偏差均值，O(log N) |
| 偏差回传队列 | List | — | 异步归档，不阻塞主流程 |

### 注意事项
- Redis 不是必须的——Phase 1-3 用内存 Map + 可选 adapter
- 滑动窗口写入用 Lua 脚本保证"写入 + 清理过期"原子性
- 所有 Redis 缓存可重建，持久化源始终是 MemoryStore

## 八、与投机编排的融合

```
推测规划 ← 仿真层（前向模拟，产出带置信度标签的候选 TaskGraph）
    ↓
并行验证 ← 编排层（多候选分支并行执行，Gatekeeper 验证）
    ↓
置信度门控 ← SemanticModelRouter（预测准确→接受提交；偏差→拒绝回退）
```

仿真层不是"小模型猜"——是"基于因果模型的预演"。每一次门控拒绝都触发偏差回传——类比反向传播。

---

## 九、与自审视系统的关系

两个系统共享同一套认知公理——"不信任声明，只信任可追溯的证据链"。

| | 自审视系统 | 仿真层 |
|------|-----------|--------|
| 预测者 | 纳西妲（架构分析 Agent） | LLM（仿真 prompt 模板） |
| 验证者 | 刻晴 + 莫娜（配对攻防） | 双视角 SimulationResult 共识 |
| 裁决者 | 纳西妲（verdict-analysis） | SemanticModelRouter 门控 |
| 偏差回传 | 自审视报告 → 下一轮改进 prompt | 偏差归档器 → 记忆系统 |

不是两套逻辑——是同一个攻防引擎挂了两组不同的 prompt 模板。

## 十一、关键设计原则

1. **不是独立子系统**：胶水代码，插在记忆系统和调度层之间
2. **LLM 就是世界模型**：因果推理交给 LLM 原生能力，不建外部推理引擎
3. **数据源是记忆系统**：原子事实链从已有检索管线获取，不新增数据源
4. **Redis 只是加速层**：毫秒级热缓存，不承担持久化职责
5. **闭环是核心价值**：感知→预测→验证→修正→再感知
6. **复用攻防引擎**：多视角共识直接复用自审视的配对攻防管线
