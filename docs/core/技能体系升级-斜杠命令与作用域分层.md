# Cortex 技能体系升级——`/` 命令系统 + 作用域分层

**定位**：让技能从"Mona 提取的机器内循环"升级为"人也能调用的可复用工作流"，同时按作用域分层减少噪音。

**对标**：Claude Code SKILL.md（`/` 触发 + 目录作用域）

**生成日期**：2026-06-19
**生成人**：昔涟（Cyrene）

## A：`/` 命令系统

### A.1 目标

在 CLI 交互模式（talk/plan）下，用户输入 `/package-gap-scan` 时：
1. 从 SkillRegistry 查找匹配的技能
2. 将技能的 steps 作为任务描述，派发给对应 agentType 的 Agent
3. Agent 执行完毕后返回结果

### A.2 现状

- CLI 已有 `cortex skill list/search/info/register/unregister/stats` 子命令
- 技能存储在 `skills/*.json`，由 SkillRegistry 管理
- 交互模式下（talk/plan），用户输入直接交给甘雨规划——没有 `/` 拦截

### A.3 设计

```
用户输入 "/package-gap-scan"
    │
    ▼
SlashCommandParser（CLI 侧，约 60 行）
    │  匹配 /xxx → SkillRegistry.get(xxx)
    │  未匹配 → "未知技能，可用 /list 查看"
    │  匹配成功 → 构造 TaskNode(type=skill_exec, payload=技能 steps)
    │
    ▼
Scheduler.dispatch(node)
    │  按技能 agentType 匹配 Agent
    │
    ▼
Agent.execute(node) → 执行 steps → 返回结果给用户
```

### A.4 实现清单

| 文件 | 改动 | 行数 |
|------|------|------|
| 新建 `packages/cli/src/services/slash-command.ts` | `SlashCommandParser`：解析 `/xxx`、查 SkillRegistry、构造 TaskNode | ~60 |
| 修改 `packages/cli/src/main.ts` | 交互模式输入循环中：`/` 开头 → 走 SlashCommandParser；否则走甘雨规划 | ~15 |
| 新建 `packages/cli/src/commands/slash-list.ts` | `/list` 内置命令：列出所有可调用的技能（只列 `user-invocable` 不为 false 的） | ~30 |
| 修改 `packages/shared/src/agent.ts` | `SkillTemplate` 新增可选字段 `userInvocable?: boolean` | ~3 |

### A.5 验收标准

- 在 CLI talk 模式下输入 `/package-gap-scan` → 调度器派发给 analysis Agent 执行
- 输入 `/list` → 列出 41 个技能中可调用的子集
- 输入 `/nonexistent` → 提示"未知技能"
- 输入非 `/` 开头的文本 → 行为不变（走甘雨规划）

## B：作用域分层（四级）

### B.1 四级作用域模型

| 级别 | 名称 | 存储路径 | 可见范围 | 覆盖规则 | 对标 |
|------|------|---------|---------|---------|------|
| **L0 跨域** | Cross-domain | `~/.cortex/skills/` | 用户的所有 Cortex 项目 | 跨域同名覆盖项目级 | Claude Code personal (`~/.claude/skills/`) |
| **L1 项目** | Project | `<root>/skills/` | 当前项目全部 Agent | 项目同名覆盖包级 | Claude Code project (`.claude/skills/`) |
| **L2 包** | Package | `packages/<name>/skills/` | 仅在该包被 Agent 处理时 | 包级独有技能仅包内可见 | Claude Code nested (`.claude/skills/` in subdirs) |
| **L3 Agent** | Agent | `agentType` 字段过滤 | 仅匹配的 Agent 类型 | 最细粒度过滤 | Cortex 特有创新 |

**跨域级的设计动机**：开发者在多个 Cortex 项目中积累的个人技能（如"我的代码审查模式""我惯用的 CI 诊断流程"）不应每个项目复制一份。`~/.cortex/skills/` 让个人技能跟随用户跨项目生效。

**覆盖优先级**：查询时从最窄到最宽——L3 Agent → L2 包 → L1 项目 → L0 跨域。同名技能以最窄作用域为准（跨域级优先级最低，被项目/包/Agent 覆盖）。

### B.2 现状

41 个技能全部在 `skills/`，`agentType` 字段已存在但仅用于标注，不用于过滤。MetaAgent 查询时走 `queryByTags(existingTags)`，不按作用域裁剪。

### B.3 解析规则

```
SkillRegistry.resolve(task, context)
    │
    ├── L0 跨域 ~/.cortex/skills/     → 始终候选（用户个人工具包）
    ├── L1 项目 skills/              → 始终候选
    ├── L2 包级 packages/*/skills/    → 当 task 涉及该包文件时候选
    └── L3 agentType 匹配            → 候选 ∩ agentType === task.targetAgent
    │
    ▼
四级合并 → 同名去重（窄覆盖宽）→ 返回裁剪后的技能列表
```

### B.4 实现清单

| 文件 | 改动 | 行数 |
|------|------|------|
| 修改 `packages/skill-kit/src/skill-registry.ts` | `SkillRegistry` 新增 `registerCrossDomain(skill)` + `registerPackageScoped(skill, packageName)` + `resolveByScope(scope)` | ~50 |
| 修改 `packages/engine/src/core/meta-agent.ts` | `_planningPrompt()` 中技能注入改为 `skillRegistry.resolveByScope({ packageName, agentType })` | ~10 |
| 修改 `packages/engine/src/bootstrap/init-skills.ts` | 启动时扫描 `~/.cortex/skills/` + `packages/*/skills/`，注册跨域和包级技能 | ~40 |
| 新建目录 `~/.cortex/skills/` | 跨域技能目录（用户手动创建，不随项目 git） | 0 |
| 新建目录 `packages/engine/skills/` | engine 包专属技能目录（暂空，预留） | 0 |
| 移动 `skills/skill-p38-*.json` | 移至 `packages/prompt-kit/skills/`（示例） | 0 |

### B.5 验收标准

- 跨域技能（`~/.cortex/skills/`）可被 `/list` 列出，可被 `/` 调度执行
- 项目技能与跨域技能同名时，项目级生效（窄覆盖宽）
- engine 包专属技能仅在该包 Agent 执行时被 MetaAgent 引用
- `agentType` 过滤生效——`code` 型技能不在 `review` Agent 的技能列表中
- `~/.cortex/skills/` 目录不存在时启动不报错

## D：架构统一度评估

### D.1 改动范围与现有架构的咬合

| 层 | 改动的包 | 改动行数 | 与现有架构的关系 |
|----|---------|---------|----------------|

| 类型 | `packages/shared` | ~3 行 | `SkillTemplate` 新增一个可选字段，向后兼容 |
| 注册表 | `packages/skill-kit` | ~40 行 | `SkillRegistry` 新增方法，不改现有 API 签名 |

### D.2 不改清单（架构一致性约束）

| 不改 | 原因 |
|------|------|
| `SkillRegistry.register()` / `unregister()` / `queryByTags()` | 现有 API 已稳定，新增方法附加不替换 |
| `SkillTemplate` 接口的必填字段 | 仅追加 `userInvocable?: boolean`，零 breaking |
| `MetaAgent.plan()` 签名 | 内部调用 `resolveByScope` 替换 `queryByTags`，外部不感知 |
| `initSkillSystem()` 签名 | 内部新增扫描，返回值不变 |
| `CommandRegistry` 结构 | 新增 `SlashCommandParser` 独立模块，不碰已有命令体系 |
| 技能 JSON 格式 | 不新增必填字段，完全向后兼容 |
