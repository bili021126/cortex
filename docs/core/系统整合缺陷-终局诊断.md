## 二、四类整合缺陷

### 缺陷 A：跨包接口类型漂移——变了实现，没变接口

| 编号 | 接口 | 声明包 | 实现包 | 漂移 |
|:--|------|------|------|------|
| C-02 | `rollback(): boolean` | memory | memory-store | 实现返回 `Promise<boolean>`，`as unknown as boolean` 强转 |
| C-3 | `IConfirmGate.needsConfirmation()` | shared | scheduler | 接口 1 参数，实现 2 参数——信任模型通过接口调用时**完全跳过** |
| C-4 | `Disposable` 接口 | shared | engine | `stop()/destroyAll()/clear()` 通过 `as unknown as` 调用——Disposable 接口已定义但**从未被使用** |
| C-1 | `IMemoryStore` | shared | memory | shared 和 memory 各自定义了**完全不同的 IMemoryStore**——同名双接口 |

**根因**：TypeScript 的 composite build 只验证声明文件存在——不验证实现是否符合接口。改了实现不需要重新编译消费方——类型漂移静默传播。

### 缺陷 B：TUI/CLI 通过 `any` 桥接器直连引擎——零编译保护

| 编号 | 位置 | 症状 |
|:--|------|------|
| T-34 | `tui-repl.ts:17` | `type EngineBridge = any` |
| CLI-1 | `types.ts:89-98` | `EngineComponents` 全字段 `unknown` |
| CLI-2 | `engine-bridge.ts:307` | `as unknown as TaskNode` 双重断言 |
| T-35 | `plan-mode.ts:191` | `item: any` 从 `JSON.parse` 无校验 |

**根因**：TUI 和 CLI 不依赖 `ICortexApi` 的具体类型——直接声明 `any` 来"避免循环类型依赖"。结果是 TUI/CLI 的每一行对引擎的方法调用都无编译期保护。

### 缺陷 C：跨包事件契约断裂——发射了但无人消费

| 编号 | 事件 | 发射方 | 消费方 |
|:--|------|------|------|
| C-15 | `ManifoldGateMaxUpdated` | scheduler | EventPayloadMap **无此条目** |
| C-3 | `MemoryPersistFailed` | shared 已定义 | memory 实现**零 emit** |
| C-4 | `GovernanceEventPayload` | shared vs engine | **两个不同定义**，`requiresDecision` 字段在代码中不存在 |
| H-关联 | `NodeComplete` dispatchMulti | scheduler | MetaAgent._onNodeComplete **永远收不到**多视角完成事件 |

**根因**：PipelineObserver 提供了总线——但总线上跑的事件没有一个"注册表"能验证每个事件都有发射方和消费方。编译期零验证。

### 缺陷 D：上下文压缩逻辑使用单次 token 值——永不触发

| 编号 | 位置 | 症状 |
|:--|------|------|
| T-27 | `query-loop.ts:339` | 压缩触发用 `resp.usage.prompt_tokens`（单次请求）而非 `sessionTokens`（累积） |
| T-28 | `query-loop.ts:316` | 警告和触发用**不同指标**——警告正确用累积值，触发错误用单次值 |
| T-32 | `token-monitor.ts:76` | 上下文比例用**累积 prompt token**——线性增长远超 100% |

**根因**：两个变量名相似、一个正确一个错误。没有集成测试验证"会话达到 95% 上下文时是否触发压缩"。

## 四、修复策略——不是一个个修，是补整合层

| 层 | 做什么 | 覆盖哪些缺陷 |
|------|------|------|
| **编译门禁** | 接口变更 → `tsc -b --force` 全量重编 → CI 拦截 | 缺陷 A（跨包类型漂移） |
| **契约测试** | shared 每个 interface 有一个对应的契约验证文件——验证所有实现方 | 缺陷 A + C |
| **TUI 桥接类型化** | `type EngineBridge = any` → `interface ITuiEngineBridge extends Pick<ICortexApi, ...>` | 缺陷 B |
| **上下文压缩集成测试** | "填满 95% 上下文 → 断言压缩触发" | 缺陷 D |
| **PipelineObserver 事件注册表** | 编译期验证每个事件类型都有发射方和消费方 | 缺陷 C |

## 五、和修宪的关系

当前宪法 v2.5.35 的七条不可变原则是单包级别的——每条原则约束单个包的行为。新宪法需要新增**跨包约束**：

- **§跨包接口契约**：`@cortex/shared` 中的每个 interface 必须有对应的契约测试。实现方变更接口行为时必须触发全量编译。
- **§事件注册表**：`PipelineEventType` 的每个枚举值必须在 `EventPayloadMap` 中有条目。禁止 `as unknown as` 绕过。
- **§TUI/CLI 桥接**：禁止 `type X = any`。TUI 和 CLI 对引擎的依赖必须通过正式接口声明。
