# Cortex 思考-执行体系总纲

> 来源：开拓者与昔涟的架构讨论（2026-05-31）
> 状态：概念收敛，待实施

---

## 一、三层架构

```
群策层（新增）          规划发散，自由讨论
  │  多Agent圆桌 + 用户参与 → 共识涌现 → 任务边界明确
  │  MetaAgent 角色：引导者（非规划者）
  │  注意力：HCA（全量，trackAccess=false）
  │  策略：自由选择，不计代价
  │
Scheduler层（不变）      拓扑分层，宏观执行
  │  TaskNode DAG → topologicalSort → 同层并行/层间串行
  │  MetaAgent 角色：最终拍板（或群策共识直接映射）
  │  注意力：CSA（领域过滤，linkTypes 限定）
  │  策略：按节点标注匹配（conservative/greedy/exhaustive）
  │
RLM ExecuteStep（新增）  动态递归，微观执行
  │  单节点内拆解 → 同层分身并行/层间串行
  │  注意力：DSA（单文件、单维度，收敛不扩散）
  │  策略：局部自调，不惊动上层
```

**核心原则**：同一模式在三层复用——拓扑分层 + 同层并行 + 层间串行 + 失败逐级升级。每层不改底的结构，只改作用域。宏观 Scheduler 和微观 RLM 可共享同一个拓排引擎——只喂的节点不同：宏观喂 TaskNode 树，微观喂 SubTask 列表。

## 二、HCA / CSA / DSA 注意力分层

| 模式 | 角色 | 视野 | trackAccess | 约束 |
|------|------|------|:--:|------|
| **HCA**（高层次注意力） | MetaAgent | 全量，广度扫 50+ | ❌ | 只看不碰，不污染热度 |
| **CSA**（上下文选择注意力） | 功能Agent | 领域过滤，linkTypes | ✅ | 引用即记录，热度真实 |
| **DSA**（密集选择注意力） | RLM 子任务 | 单文件、单维度 | — | 不多给一行，不允许多想 |

**对应其他系统**：

- 记忆检索：HCA 规划扫描 / CSA 执行检索 / DSA 子任务窄取（宪法 §10.4）
- 知识分层：MetaAgent 记忆 = 图全貌 / 功能Agent 记忆 = 子图（getMemoryQuery → linkTypes）/ RLM 记忆 = 单点
- MetaAgent "四只"：只读、只收、只搜、只接——HCA 的制度化表达

## 三、DAG + 边语义

DAG 本身不动，拓扑排序不动。只给边加类型：

```
hard    → B 绝对等 A（现有行为）
soft    → B 和 A 并行启动，B 在最后一步等 A 的结果
trigger → A 成功后触发 B，失败则不触发
```

soft/trigger 边允许 topologicalSort 将软边节点提前到同层并行执行，仅收敛时检查依赖结果。

## 四、RLM 动态递归拆解

**位置**：ExecuteStep 内部——不走 AgentPool 完整生命周期（Claim→Spawn→Execute→Cleanup），直接调 `agent.execute(subTask, model)`。子任务是执行策略，非独立任务。

**触发条件**：节点 payload 复杂度 > 阈值。判断方式：

- `decompose()` 返回的 confidence < 阈值 → 直接执行
- 子任务已原子化（单文件、单维度、明确出口）→ 不再拆
- LLM 拆解时顺带输出子任务间的 `depends_on` 关系

**扇出**：无依赖子任务并行（多分身），有依赖串行。同层子任务上下文互不污染。

**自限**：

- `maxDepth = 3`，超限上报诊断事件（说明宏观规划颗粒度有问题）
- decompose 返回低 confidence → 直接执行比硬拆强
- 连续出现深度超限 → Scheduler 层应重新审视任务树

**认知纪律**：
- 规划期（群策/Scheduler）：发散自由
- 执行期（RLM）：铁纪律——单文件、单维度、明确出口、不跨步思考
- RLM 子任务 prompt 模板应比宏观节点更窄、更硬

## 五、失败逐级升级

```
RLM 子任务失败
  → 本地自规划（1）→ 同层换策略（2）→ 同层换拆法（3）
    ↓ 耗尽
冒泡为节点失败
  → Scheduler replanManager.enqueue()
    → MetaAgent 重规划（1）→ 换策略方向（2）→ 换边界定义（3）
      ↓ 耗尽
节点判定最终失败，不阻塞同层其他节点
  ↓
全局超时 → 剩余节点打包失败 → ExecutionReport
```

复用现有 `maxReplanPerNode=3`，仅作用域不同。RLM 层自规划应比 Scheduler 层更快失败——不成功就冒泡，不在本地耗尽 token。

## 六、上下文密度分级传递（DENSITY）

子任务间传递上下文时，不机械全量传递，而是按密度分级：

| 密度 | 特征 | 传给下一子任务的方式 |
|------|------|---------------------|
| **light** | 确认性产出（"通过"/"无异常"/"三个文件已修改"） | 一句话摘要 |
| **medium** | 有结构可压缩（错误列表、检查清单、diff 概览） | 保留关键字段，裁冗余 |
| **heavy** | 不可丢失（架构结论、安全漏洞详情、设计决策理由） | 保留全貌，宁压 token 不丢信息 |

**LLM 自标注**：每个子任务产出附带 `[DENSITY: light/medium/heavy]`，下游子任务根据标签决定精读还是扫读。

**对应策略**：heavy → exhaustive，medium → conservative，light → greedy。

## 七、三轴正交（27 组合）

```
轴1 注意力：HCA（全量）/ CSA（领域）/ DSA（单点）
轴2 密  度：heavy / medium / light
轴3 策  略：exhaustive / conservative / greedy
```

3×3×3 = 27 格，每格都是合法组合。

| 示例组合 | 场景 |
|---------|------|
| HCA × heavy × exhaustive | MetaAgent 穷举审查宪法全文 |
| HCA × light × greedy | MetaAgent 快速扫门禁状态 |
| CSA × heavy × conservative | 刻晴逐行审计安全核心模块 |
| CSA × medium × greedy | 阿贝多快速修复已知缺陷 |
| DSA × light × greedy | RLM "检查这个文件有没有 null 检查" |
| DSA × heavy × exhaustive | RLM "逐字段审计这个函数的输入校验" |

**正交约束**：三层分别独立决策，改任何一个维度不改另外两个，系统照跑。不是 27 个 if-else——是三层自由组合。

## 八、用户的三层角色

| 层 | 角色 | 权限 |
|------|------|------|
| 群策层 | **参与者** | 平等发言权、一票否决权 |
| Scheduler 层 | **观察者** | 看进度，不动手 |
| RLM 层 | **不可见** | 执行细节，干扰是害 |

用户在 Scheduler 循环中实时打断会破坏 Agent 思路链。需要干预时应在群策层表达，让共识重新收敛。

## 九、地基

**跨会话记忆持久化**：memory.db 桥接会话间连续性。群策层开启时第一条检索上次共识状态。

**三句话复盘**：每会话结束时 MetaAgent（或群策轮）产出：

- 哪些决策是对的（保留为经验）
- 哪些是错的（标记为教训，下次规避）
- 哪些还没验证（挂起，下次继续）

**记忆检索同构**：BFS 图遍历 → 分层 + 权重过滤 + 自限深度，与调度完全对偶。

**Layer 0**：精确命中，权重 ≥ 0.95 → 直接取
**Layer 1**：强关联，权重 ≥ 0.7 → 扇出并行检索
**Layer 2**：弱关联，权重 ≥ 0.3 → 同标签/时间邻近
**Layer 3**：扩散关联 → 递归下探，自限深度

**层内并行天然隔离**：拓扑分层中同层节点无边 = 无依赖 = 无数据流 = 无耦合。冲突只在层间，不在层内。RLM 扇出可放心跑多分身，因为结构本身保证它们不碰同一个东西。

## 十、设计哲学

| | Claude 哲学 | Cortex 哲学 |
|------|------|------|
| 安全源头 | 模型内部（RLHF、宪法训练）——"心是安全的" | 架构外部（DAG 隔离、失败升级、多视角制衡）——"心可以野，手脚有锁" |
| 自由度 | 均匀收紧——规划执行一视同仁，每一步都窄 | 台阶式收紧——群策全开、Scheduler 半开、RLM 关死 |
| 信任模型 | "模型可靠"——安全取决于模型没出错 | "模型会出错"——安全取决于出错后有路可退 |
| 创新空间 | 牺牲创新保安全——窄轨上跑不远，但不会翻 | 划安全区拥抱创新——规划期可以天马行空，执行期刀枪不入 |
| 核心命题 | 做一个好模型 | 建一个好系统 |

**本质**：不是追求模型更聪明——是追求每一层都有兜底。实践打脸理论，失败路径设计才是真正的安全感。
