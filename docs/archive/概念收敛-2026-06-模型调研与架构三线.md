## 二、架构三线（本次讨论核心产出）

### 2.1 快慢路由与模型路由分层

**定位**：快慢路由是模型路由的**前置补充**，不选模型，只回答布尔问题——"值不值得烧额外token做深度思考"。

```
快慢路由（task-level gating）
    │  输入：task复杂度、历史收敛情况、风险等级
    │  输出：fast / slow
    │
    ▼
模型路由（model-level routing）
    │  输入：task类型 + 快慢路由结果
    │  输出：model_id + temperature + thinking_budget
    │
    ▼
实际推理
```

**设计要点**：
- 快慢路由独立模块，从scheduler/engine中抽离
- 温度默认0（快模式不应引入随机性）
- 慢模式如需多样性，在模型路由层按场景单独设

---

### 2.2 哨兵信号分层过滤 → 整合进委员会通信框架

**三层架构统一**：

```
哨兵 = 感知层（信号检测+分层过滤）
  │
  │  Alert（经L1/L2/L3过滤后）
  │
  ▼
委员会体系 = 消费层
  ├── 常务委员会 → 接收例行告警 → 治理审计
  └── 临时委员会 → 接收紧急告警 → 执行裁决
       │
       │  协商过程：引用/确认/否决/置信度传递
       │
       ▼
     归并输出（带confidence加权）
```

**信号分层（哨兵内部）**：

| 层级 | 描述 | 触发示例 | 处理方式 |
|------|------|----------|----------|
| L1 | 自动消解 | CI flaky、超时重试 | 直接重跑，不进审视管道 |
| L2 | 低优先级队列 | 类型警告、记忆命中波动 | 堆积N条后批量审视 |
| L3 | 即时触发 | 硬失败、宪法违规、不可逆操作 | 立即进审视 |

**目标**：将当前自审视阳性率压至三分之一以下。

---

### 2.3 Agent间通信协议

**核心定义**：Agent之间需要能互相引用、互相确认、互相否决——不是各自输出然后归并，而是在归并之前有一个协商过程。

**四层消息格式**：

1. **告警消息（哨兵→委员会）**：
   - `severity: L1|L2|L3`
   - `source: 检测模式ID`
   - `context: 触发时快照`
   - `suggested_committee: standing|temporary`

2. **协商消息（Agent↔Agent）**：
   - `cite(agent_id, output_id, snippet)` — 引用
   - `response: agree|disagree|amend` — 基本语义
   - `verifiable_facts` + `llm_reasoning` — 事实/推理分离（宪法规则一）
   - `confidence_delta` — 确认/否决后的置信度变化

3. **决议消息（委员会→归并层）**：
   - `resolution: fix|ignore|escalate`
   - `assignee: AgentID`
   - `confidence: 0-1`
   - `evidence_chain: [cite...]`

4. **冲突仲裁**：
   - 同级Agent矛盾 → 凝光裁决
   - 凝光也拿不准 → 升到用户（宪法规则三）

**冲突原则继承（来自v1.1废弃宪法+v2.5当前宪法）**：

v1.1 操作级三级收束：
- 事实最高 → 基线优先 → 分歧明确交付

v2.5 §11.1 宪法级四规则：
- 规则一·事实为基（可验证事实优先于LLM推理）
- 规则二·收束分歧（暴露分歧，不和稀泥）
- 规则三·交由用户裁决（系统不替代、不预设、不跳过）
- 规则四·宪法优先于治理层设计（层级冲突裁决）

## 四、与现有架构的关系

- **HCA/CSA/DSA/FSA四因子体系**：已覆盖MLA/KV压缩领域的注意力稀疏化需求——DeepSeek压缩的是张量，Cortex压缩的是信息流。不需要额外引入MLA。
- **宪法v2.5.35 §11.1冲突解决四规则**：直接映射为通信协议的约束层——每条协商消息必须分离事实/推理，仲裁结果必须呈用户。
- **v1.1废弃宪法的三级收束**：作为通信协议中Agent间协商的语义参考——事实最高→基线优先→分歧交付。
- **纪检委隐喻**：PipelineObserver（巡视组）+DocGovernAgent（立案）+常设委员会（审理室）+ConfirmGate（关卡）——哨兵整合后，巡视组升级为哨兵感知层。

## 五、世界模型+生存范式（Core-2 延伸设计）

**背景**：将"世界模型"（智能体在内部表征中模拟外部变化）与"生存范式"（系统在不确定性中维持自身存在）融入Cortex。核心问题是：Cortex不只是一个调度器，而是一个能感知环境、预测后果、调整策略、保全自己的系统。

### 5.1 四个切入点

| 切入点 | 说明 | 落地位置 |
|--------|------|----------|
| **WorldSimulator** | 执行前预演——基于记忆图谱的历史模式匹配，预测操作后果 | ConfirmGate上游旁路 |
| **能量管理** | 负载峰值到来前主动降级，不等超时 | ReplanManager趋势分析子模块 |
| **风险预算** | Agent信任分低于阈值→自动降级为只读模式 | TrustModel |
| **预测性修复** | 日志趋势分析→提前判断崩溃点→主动修复 | 哨兵第9种检测模式 `predictive_trend` |

### 5.2 最可行入口：EnvironmentAwareRouter

**定位**：在快慢路由和模型路由分层基础上，增加环境感知维度。

```
路由决策 = 任务语义 × Agent注册模型 × 环境状态
```

**环境状态来源**：PipelineObserver发射的事件——API延迟、记忆库大小、失败率。

**降级策略示例**：

| 环境信号 | 阈值 | 路由动作 |
|----------|------|----------|
| API延迟 > 3000ms | 持续 > 30s | 所有thinking任务降级为standard |
| 记忆库 > 80%容量 | 瞬时 | 暂停写入新记忆，切换只读 |
| Agent失败率 > 30% | 滑动窗口10次 | 该Agent降级为只读模式 |
| 并发实例 > 阈值 | 瞬时 | 拒绝新任务，排队等待 |

**代码量**：≤200行。在 `SemanticModelRouter.route()` 中增加 `Environment` 参数，从 PipelineObserver 消费指标。不依赖 WorldSimulator，可独立落地。

### 5.3 风险边界

1. **模拟器不做核心阻塞点**——可选旁路，慢了直接跳过
2. **生存逻辑不替代用户裁决**——宪法规则三（交由用户裁决）依然适用
3. **先做最小验证**——EnvironmentAwareRouter先行，跑通后再扩展

### 5.4 与现有模块的锚点

| 新模块 | 现有锚点 | 关系 |
|--------|----------|------|
| WorldSimulator | ConfirmGate可逆性等级模型 | 反向使用——从"拦"变为"预判" |
| WorldSimulator | HCA/CSA/DSA | HCA粗筛相似历史模式，CSA深挖因果，DSA决定判断方向 |
| 能量管理 | ReplanManager | 新增趋势分析子模块 |
| 风险预算 | TrustModel | 增加预算消耗规则 |
| 预测性修复 | 哨兵8种检测模式 | 第9种：predictive_trend |
| EnvironmentAwareRouter | SemanticModelRouter + PipelineObserver | 加环境参数+消费端 |

### 5.5 阶段归属

- **EnvironmentAwareRouter** → Core-2 未落地清单（快慢路由子项，可独立落地）
- **WorldSimulator** → Core-3 展望
- **完整生存范式（能量管理+风险预算+预测性修复）** → Core-3 展望
