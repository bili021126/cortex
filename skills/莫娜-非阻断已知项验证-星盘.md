## 逐项验证详情

### 1️⃣ embedding 存储格式不一致

**原声称**：`JSON.stringify` 写入 TEXT 列，`_parseEmbeddingBlob` 期望 Buffer，跨会话向量召回降级。

**验证路径**：
- `packages/memory-store/src/memory-store.ts` — 适配器层 `write()` 中 embedding 作为 `number[]` 传入 `this._backend.write(input)`
- `packages/memory/src/implementations/AbstractMemoryStore.ts:491` — `embedding: f.embedding`（类型 `number[] | undefined`）
- `packages/memory/src/implementations/FileBasedMemoryStore.ts:persist()` — `JSON.stringify(entry)` 序列化整个 MemoryEntry，embedding 作为 JSON 数组自然序列化
- `FileBasedMemoryStore:load()` — `JSON.parse(raw)` 恢复，embedding 还原为 `number[]`

**搜索 `_parseEmbeddingBlob`**：全仓无匹配文件。旧 `engine/src/memory/storage.ts` 已随 `@cortex/memory` 提取移除。

**结论**：❌ **不再存在**。架构重构（引擎层适配器 + `@cortex/memory` 后端层）后，embedding 通过标准 JSON 序列化/反序列化路径正确流转。

---

### 2️⃣ `writePending()` 跳过去重

**原声称**：半成品记忆不执行 SHA256/向量去重。原报告标注 "设计如此"。

**验证路径**：
- `memory-store.ts:writePending()`（~line 461）：
  ```
  writePending(input: MemoryWriteInput): string {
    input = this._validateWrite(input);  // 仅校验生命周期 + embedding 维度 + preWriteHook
    return this._backend.writePending(input);  // 直接委托后端，无 embedding/SHA256/向量去重
  }
  ```
- `memory-store.ts:commitMemory()`（~line 478）：
  ```
  commitMemory(memoryId: string): boolean {
    const ok = this._backend.commitMemory(memoryId);
    if (ok) {
      this._enrichPendingEntry(memoryId).catch(...)  // 异步补全 embedding + dedup 缓存 + BM25
    }
    return ok;
  }
  ```
- `memory-store.ts:_enrichPendingEntry()`（~line 492）：执行 embedding 生成、content_hash 去重缓存预热、向量索引缓存、BM25 索引更新

**证据**：writePending → 无去重 → commitMemory → _enrichPendingEntry 异步补全

**结论**：✅ **设计如此**。Pending 态记忆尚未定型（两阶段提交第一阶段），去重逻辑后移到 commitMemory 触发。

---

### 3️⃣ `_contentHash` 不持久化

**原声称**：`(entry as any)._contentHash = contentHash` 仅附加到内存对象，SQLite DDL 无此列，反序列化时不读取。

**验证路径**：
- `shared/src/memory.ts` — `MemoryEntry.content_hash: string` 为正式字段（§4 工程层）
- `AbstractMemoryStore.ts:491` — `content_hash: f.content_hash ?? ""` 存入 MemoryEntry
- `AbstractMemoryStore.ts:709` — Pending 条目 also stores `content_hash: p.input.content_hash ?? ""`
- `FileBasedMemoryStore.ts:persist()` — `JSON.stringify(entry)` 序列化完整对象，含 content_hash
- `FileBasedMemoryStore.ts:load()` — `JSON.parse(raw)` 恢复含 content_hash

**旧架构追踪**：旧 engine `storage.ts` 中 `(entry as any)._contentHash = contentHash` 附加到内存对象但不反序列化——该文件已随 `@cortex/memory` 提取删除。

**结论**：❌ **不再存在**。content_hash 已从"走私字段"正式化为 MemoryEntry.content_hash，via JSON 正确持久化到磁盘。

---

### 4️⃣ `updated_at` 始终等于 `created_at`

**原声称**：语义错误但未被任何查询使用。

**验证路径**：
- `shared/src/memory.ts` — `MemoryEntry` 接口字段搜索：无 `updated_at`、`updatedAt`、`updated`
- 全仓 grep `updated_at|updatedAt`：memory-store.ts、shared/memory.ts、AbstractMemoryStore.ts 中均无匹配

**结论**：❌ **不再存在**。v3 类型重构（四层切割）移除了 `updated_at` 字段，`MemoryEntry` 仅有 `createdAt` 和 `lastAccessedAt`。

---

### 5️⃣ `metadata` 默认值 `"{}"` 而非 `null`

**原声称**：语义不干净但不影响功能。

**验证路径**：
- `shared/src/memory.ts` — `MemoryEntry` 接口：无 `metadata` 字段
- `shared/src/memory.ts` — `MemoryWriteInput` 接口：无 `metadata` 字段
- `AbstractMemoryStore.ts` — `write()`: `content_blob: f.content_blob as Record<string,unknown>`，无 `"{}"` 默认值
- `AbstractMemoryStore.ts:_vw()`: 校验 `if (!i.content_blob || typeof i.content_blob !== "object")` 确保传入值必须为对象

**结论**：❌ **不再存在**。`metadata` 字段在 v3 类型重构中移除，`content_blob` 作为替代。无 `"{}"` 默认值逻辑。
